# PLAY-TARROW-INVESTIGATION-1 — candidate development checkpoint

Owning issue: https://github.com/pandasmoon14-hub/Test/issues/552.
Baseline: merged #549, main `21187d11c10899e0966b76cd089affaeb8df9134`.
This is an **initial candidate under review**, not adopted native canon or a complete #552 certificate.

The opt-in `tarrow-investigation` route adds requester-owned, read-only history
and comparison of previously admitted facets, with explicit absence/unsupported
results and no world-truth refresh. Comparison never selects a culprit or true
report. It follows historical admission order and marks origin/delivery as
logical sequence identifiers rather than dates. Query resolution uses only the
requester's admitted subjects, not hidden fixture object lookups. Existing
actor movement, work, communication and material choices remain executable.

The variant uses a separate checkpoint format and binds its query, disclosure,
and case profile identity. The already visible immediately prior reporter is
captured only at the point a qualified relay is delivered; later history queries
do not dereference another actor's private source event. Old actor checkpoint
formats are not rewritten or converted. Cases `cleanup`, `assembly`, and
`relay` vary valid actor profile/order and opportunity, but do not yet
establish the #552 minimum neutral-root generated campaign corpus.
