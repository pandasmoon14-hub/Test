# Portable runtime delivery protocol

Apply these procedures in ordinary Chat, Work, local agents and human-assisted
sessions. They preserve engineering expectations; they cannot supply absent
models, tools, permissions or quota. Current doctrine and scoped owner decisions
remain authoritative. Keep historical Astra software identifiers where required.

## Select substantial coherent work

- State the new player/world possibility, context and durable consequences.
  Player freedom and world consistency are joint priorities. An open intention
  space does not imply automatic success or universal implementation.
- Inventory the capability family before choosing the largest coherent package
  whose dependencies, ownership, uncertainty and acceptance can be managed.
  One bounded concern can span many related verbs, objects and systems. Do not
  split into decorative micro-PRs or inflate scope with unrelated features.
- Compare representation, meaningful generation and executable simulation.
  Identify where the recent sequence stalled and what a ready package unlocks.
  Do not wait for universal rules before generating supported families. Generated
  and authored instances must use the same applicable mechanics and qualification.
- Classify missing content, missing implementation, routing limits, incompatible
  assumptions and genuinely missing semantics separately. A design question is
  not automatic authorization to implement its answer or choose it next.

## Recover sources and authority once

Keep one packet: objective, scoped approvals, source/main/branch identities,
existing owners/interfaces, relevant decisions, acceptance map, evidence pointers
and first unmet condition. Resolve current source versions before changing
meaning. Reuse already-read valid material. Do not reconstruct settled decisions
from conversation memory or reload an entire corpus for one narrow question.

For canon-sensitive work retrieve approved definitions, original decisions and
later supersession. Access sources through available authorized tools. If a
source is inaccessible, name exactly which dependency is blocked; continue
independent approved work. Never infer native rules from fixtures, descriptive
prose, external fiction or a document's production status.

Treat external sources as research pressure: source-local observation → normalized
requirements → independent Myravant proposal → approved design → implementation.
Preserve provenance barriers and distinguish universal canon from campaign facts.
Do not copy donor content under superficial renaming.

## Deliver complete vertical capability

Map the actual parser → application → qualified owner transition → commitment →
receipt → persistence/replay → audience-safe presentation path before editing.
Confirm source paths rather than treating a module name as semantic authority.

For each applicable route deliver:

1. Intent, method, participants, resources, locality and opportunity qualification.
2. Existing owner procedures, authoritative state changes and explicit refusal,
   ambiguity or partial-progress semantics. Requalify mutable context at execution.
3. Public installed-client access with understandable affordances and feedback.
   Preserve meaningful modifiers; avoid recognizer collisions or fixture-name hacks.
4. Cross-system consequences: custody, access, material/resource conservation,
   time, evidence and relations as the approved mechanics require.
5. Stable identity, deterministic chronology, legitimate acknowledged prefixes,
   save/restore and compatible replay. Preserve old bindings or use approved,
   versioned migration/rejection rather than silently changing old campaigns.
6. Independently configured transfer and generated instances where meaningful;
   prove different properties affect possibilities, not merely changed digests.

Keep state/RNG/time/history/commitment under deterministic backend authority.
Models interpret, propose and narrate within qualified information. Preserve
identity/embodiment, actor/requester, consent/control/custody, knowledge/truth,
observation/report/performance and proposal/commitment distinctions. Do not expose
hidden facts through refusal, debug output or presentation. Avoid humanoid,
combat-only or single-body assumptions unless explicit approved profiles require them.

## Verification and independent acceptance

Build one risk-based acceptance map tied to the playable goal. Cover ordinary
use, alternatives, invalid/stale context, refusal, contention, interruption,
conservation, hidden information, persistence and restart where affected. Test
exact boundary adversaries directly. Do not claim a fixture Cartesian product
or universal generality from representative cases.

During development run focused new and cross-interface checks. Resolve substantive
review and reproduced regressions before freezing the candidate. Then run required
full local/platform checks, retained evidence runners, installed journeys and
mutations as specified by the owning contract. Preserve separately required
baseline/extraction certification. Do not invent counts or treat optional skips
as complete coverage. Tests, engineering-authored play, independent assessment,
blind acceptance and human play are distinct evidence classes.

Review may be sequential in one chat: mechanical coherence, implementation,
canon compatibility where affected, persistence, privacy and player meaning.
Self-review is not independent review. Delegate only available, authorized,
nonoverlapping tasks with bounded sources and concrete expected benefit. There
is one integration owner, not three parallel investigations of the whole package.

## Efficient execution and evidence reuse

Measure the long installed/replay path early when performance or CI capacity is
material. Optimize measured hotspots with comparable equivalence evidence. Do
not delete validation, reduce sensing, remove checks or raise unapproved budgets.
Keep all required checks when scheduling independent jobs separately.

Freeze once focused integration and substantive review are green. Record source
SHA, dirty-state fingerprint, command, environment, exit status, logs and remaining
gates. Reuse valid outputs, export already-executed evidence when contracts allow,
and summarize logs instead of repeatedly flooding context. No fixed line count,
test count, number of agents or speed multiplier is a quality target.

Before an expensive rerun state what changed/failed, which evidence is invalidated
and the minimum required rerun. Renew final-head certification after executable
changes as required. Do not use an old head's passing run as a changed candidate's
certificate. Documentation-only changes still need applicable checks and must not
be mislabeled as prior exact-head certification.

## Tools, stopping and continuity

- With authorized write/execution tools, implement, test and prepare the actual PR.
  Do not substitute a plan for available authorized work. Without writes, produce
  a source-bound applicable patch; without execution, use local/CI results and
  leave certification pending. Never claim absent tools or offline autonomous work.
- Ask only for a consequential missing canon/authority/scope decision after
  checking existing approvals. Continue independent ready production. Preserve
  explicit merge gates and verify exact source/checks immediately before merging.
- Finish useful work before yielding. When only external CI remains, save a
  compact checkpoint in its owning PR and return the SHA, run link, completed and
  pending checks, and exact next retrieval. Resume next user turn; do not spend
  repeated model turns polling unless explicitly asked to stay through completion.
- Stop at approved acceptance. Route unrelated discoveries to existing trackers
  with concrete triggers; maintain water-domain extension triggers where affected.
  Do not silently select the next package or close broader milestones from a
  narrow green suite. Distinguish measured elapsed time from account usage.
