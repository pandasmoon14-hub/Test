# Compact delivery records

Use these fields inside existing owning issues/PRs. They are development notes,
not gameplay schemas, a new approval ledger or evidence of tests being executed.

## Capability contract / acceptance map

- Player/world thesis and meaningful constraints/consequences.
- Family inventory; admitted package; dependencies and justified exclusions.
- Authorization source and boundaries: proposal / implementation / certification /
  tracker updates / merge. Preserve later owner answers and supersession.
- Existing owners and actual parser/application/domain/presentation entry points.
- Reads/writes, qualification, ordering, refusals and partial-progress semantics.
- Native content versus neutral fixtures; variation/generation validity.
- Persistent state, compatible bindings, replay and acknowledged-prefix recovery.
- Acceptance rows: scenario → observable goal → named test/journey → source/run →
  result/limits. Include affected boundary adversaries and negative controls.
- Full platform/evidence requirements; actual cost/headroom; remaining gates.

## Continuation checkpoint

- Exact inspected main, branch, candidate head and dirty-state status/fingerprint.
- Authorized outcome, approval links and current owning issue/PR.
- Changed paths and implemented/player-visible/persistent capability.
- Observed checks: command, source, environment, result, skips, log/artifact link.
- External run link/status and exact source binding; unavailable checks explicit.
- First unmet condition, demonstrated blocker and exact next action.
- Decisions needed, independent work ready, and which evidence a new change invalidates.

Keep volatile status in the owning PR, not copied across several competing files.
A local-only commit is not a shared baseline. Pending CI is not certification.

## Review record

Cover mechanical coherence, source ownership, vertical/public integration, generated
or alternate-profile transfer, qualification/privacy, persistence/replay, regression
and performance. Name the inspected head and concrete findings. Label self-review,
separate automated assessment, independent review and human acceptance distinctly.
